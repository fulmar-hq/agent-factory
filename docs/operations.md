# Operations

The controller uses Bun's native SQLite in WAL mode, `BEGIN IMMEDIATE` for reservations, and an append-only debit ledger. Its only runtime dependency is Zod. There is no polling model, queue service, container platform or hosted database.

## Policy and evidence

`config.yaml` is read and validated by the controller. Only the explicit owner-run `factory add-project` setup command appends enrollment entries. Schedule is fixed to 20:00 QA and 21:30 Production, America/Toronto; another schedule is refused. Concurrency starts at the configured limit; heavy tests have their own slot. Prefix-overlapping allowed paths conflict. Claims accept printable ASCII paths only, remove `.` segments and compare lowercase paths, including retained claims. Non-ASCII claims (including ß and dotted/dotless I) are refused rather than approximating APFS case folding. Retained non-ASCII claims block admission until their owner reconciles and archives custody. Absolute paths, `..` segments, empty/root paths, backslashes and patterns are refused; spelling variants cannot allocate a second writer. Unsplit work above four helper-hours or spanning backend and screen is refused. Enrollment and owner assignment come from config. GitHub state labels alone cannot supply a bounded brief: Ready also needs the complete `factory` block and exactly one matching `ready:<digest>` label. With the owner token, run `bun scripts/control.ts approve-intake REPO ISSUE OWNER-RECEIPT` after reviewing the block. It validates the intake, creates a repository label and attaches that label plus `state:ready` using the signed-in GitHub account (triage+ authority). SHA-256/base64url binds repo, issue number and exact block bytes; body edits to the block invalidate approval, including edits before the next tick. Remove stale digest labels and reapprove to accept a reviewed edit. The command logs the receipt and undo. Label create/edit interruption fails closed; repeat approval to recover. A final launch reread validates the digest and reconciled ticket before reservation. Read/validation failures reserve nothing. Reservation, start claim and the synchronous supervisor-spawn attempt share a SQLite transaction; a synchronous spawn failure rolls it back so the ticket can retry. The supervisor cannot take custody until that transaction commits. A later label failure is logged without releasing the launched worker’s claim. Public authors cannot attach approval labels without repository label authority; anyone holding that authority can approve work. GitHub refresh is bounded to 1,000 issues per enrolled repository; hitting that limit blocks that repository's admissions and marks the source truncated. API errors keep old snapshots with a visible source error.

A private `repositories.json` maps enrolled `owner/repo` names to existing local Git checkouts. Every helper gets a new branch and worktree under the private installation. Existing work is not reset or cleaned. The launcher retains every session claim after completion. A label reset or estimate change alone cannot replay a claim. A new numbered attempt is allowed only when every prior attempt is archived with a recorded custody receipt, its original digest is known, no prior attempt has a recorded PR, and fresh all-state GitHub readback finds no PR for any prior assigned branch. The owner-token approval control must record a receipt for a NEW exact block digest after the latest custody archive. The normal fresh intake reread and all admission gates still apply. A live or unknown prior session, unknown PR readback or reused digest refuses admission. Reservation, attempt number, digest uniqueness, claim and spawn stay in the same immediate transaction, so concurrent ticks can claim a digest once. A synchronous spawn failure rolls that transaction back; uncertain starts retain custody. Each attempt gets its own workspace, logs, claims and conservative debit; no old work, claim or charge is reset. Initial session IDs stay unchanged. The SQLite upgrade retains original rows in `sessions_v1_archive`, preserves their foreign-key claims and derives legacy digests only from approval receipts preceding the original reservation. Missing legacy provenance refuses retry. Undo through a signed revert after reconciling affected attempts; retain the migration archive and operational history.

Private `readings.json` accepts `codex` and `claude` readings with `observedAt` (epoch milliseconds), `source`, and one or more `windows` of `{used: 0..1, resetsAt: epochMilliseconds}`. Each provider is validated independently. Ticks also read only rate-limit metadata from bounded tails of the 20 newest local Codex rollouts across session date directories. The optional `usage_windows.rule` selects the exposed-window policy: at least one fresh native window is required, and every exposed window is checked. Native readers retain provider, window name and available duration; the board labels a single seven-day window “weekly only”. Without that explicit policy, the legacy two-window minimum remains. Private readings without native provenance cannot satisfy the exposed-window policy. No reset time manufactures a fresh zero. 70% admits only high-benefit work; 90% in either window refuses all starts. Unknown or older-than-15-minute data refuses starts.

`billing` in readings has `observedAt`, `month` (`YYYY-MM` Toronto), `postedCents`, `unpostedCents`, `fixedCents`, `projectedCents` and a source `receipt`. It must be less than 24 hours old. Available AWS money deducts posted gross, unposted, fixed liabilities, reserve and this month's commitments. Projected and actual gates use config. Posted plus unposted spend at or above the actual stop, or projection at or above the monthly ceiling, latches a stop until an owner decision clears it. Each new stop after a clear gets a separate append-only event. Unknown, stale, future, wrong-month or held billing and a latched stop refuse every AWS admission, including declared zero-cost tickets. Other wallets default to the configured authority (normally zero); they cannot borrow. Negative, fractional, infinite and racing requests are refused.

Reservations debit the entire authorized worst-case cost immediately and irreversibly. Finished or stopped work does not refund itself. Posted billing may overlap these commitments: this deliberately underestimates remaining money until month end. There is no agent-facing funding or settlement credit. All inputs, debits, custody changes and decisions carry stable IDs or unique decision IDs, timestamps and undo notes. Corrections append evidence.

## Native workers

Codex runs `codex exec --ignore-user-config --ignore-rules --json` with `approval_policy=never`, the named `factory` permissions profile, the requested model and effort. The profile grants minimal system reads, read-only installed toolchains (`/Library/Developer`, `/opt/homebrew`) and temp roots, and write access only to the worktree; command network access is disabled by default. The qualified Alido delivery profile adds explicit writes to its standalone `.git` and in-worktree scratch directory, read-only Bun/Node executables and the existing public signing key, and exactly the existing SSH agent and delivery Unix sockets. The native network proxy has an empty domain allowlist and no approvals. Direct internet access remains refused. Git global/system config is disabled inside workers; no private key or GitHub credentials enter the worker environment. Broader home-directory reads are absent. Temp writes are refused; tools needing scratch files must use the worktree. Project config cannot override command-line permissions.

Claude print runs in native safe mode (customizations disabled, permissions still active), with empty setting sources, strict MCP configuration, no Chrome, no permission prompts, restricted file tools, an explicit tool list and `acceptEdits`. The supervisor generates a new mode-0600 `worker-SESSION.jsonl.settings.json` beside each retained worker log and passes its path to `--settings`; existing files are never overwritten. Native settings block file-tool reads and writes outside working directories and deny private controller assets. For worktrees nested under the private root, deny paths cover its existing siblings at every ancestor, without denying the worktree itself. The native shell sandbox is required, forbids unsandboxed retries and excluded commands, denies private writes, and denies home reads except the worktree. Its shell runtime retains a native per-user temporary directory; qualify that boundary separately. `opus` and `opus-5.5` map to the exact `claude-opus-5-5` model; the advisor tool is disabled and `switchModelsOnFlag: false` refuses automatic safeguard fallback. Streamed message models, final model usage and own-transcript model/effort receipts are checked: any other reported model pauses the session. Refusals and error results cannot count as successful completion. Optional background mode is diagnostic and needs its own qualification.

Native IDs come from actual JSON events. A 500 ms reader resolves only that ID's own Codex rollout or Claude project transcript, checks native/worktree custody, and persists the observed model and effort. It never picks the newest unrelated file. Missing or conflicting identity prevents successful completion. Receipt reads are incremental and bounded; completion requires a fully read tail. CLI subscription status is verified without a model call; API key and third-party route sign-ins are refused. Worker environment is allowlisted and excludes controller tokens, API keys and GitHub token variables. Workers never receive the signing socket or GitHub/AWS credentials.

Codex app threads need foreground `open codex://threads/ID` to wake; background `open -g` is insufficient. That Mac handler does not prove phone access. CLI links, app visibility, mobile steering, actual model and account qualification must be independently verified. `claude agents --json` can verify background custody. Automatic admission uses supervised print mode only; background support is available for qualification, not silently treated as qualified print mode.

`qualifications.json` is protected controller evidence, keyed by provider. Each record requires `qualified`, `subscription`, `policyIsolation`, `liveAccounting`, and `stopVerified` all true. `phoneVerified` must be true unless the Coordinator explicitly writes `"waiver": {"phone": "deferred"}` while leaving `phoneVerified: false`. This waiver applies only to phone access; it cannot waive another gate. Records also require `version`, exact configured `model`, `effort`, future `expiresAt` and an `evidence` receipt. No qualification file or synthetic qualification is installed by prepare. Missing evidence blocks launches.

**Same-user file modes are not an isolation boundary.** Admission still requires native evidence for the installed harness boundary. The configured sandboxes restrict model tools, rather than the trusted harness process that reads its own subscription credentials and writes its transcripts. Do not assert `policyIsolation` from flags, prompts or fixture tests. Prove denied controller/account reads, outside writes and the effective policy in real runs. Claude file tools and shell tools have different enforcement and both need review. No policy identity provisioning or account migration is performed here.

Accounting is monotonic against the frozen baseline. Day-1 `ticket_budget_default` sets 8M observed input+output tokens and 30 active-process minutes as default estimates; checkpoint at 14.4M tokens or 54 minutes and pause at 16M or 60 minutes, whichever arrives first. Cached tokens are included once in totals and shown separately. Larger approved bounds remain explicit. Comparable completed native receipts can raise future reservations, but cannot reduce explicit approved intake bounds; the old completed-model-turn p90 calibration does not override Day-1 ticket defaults. Existing reservations keep their original frozen bounds. A paused process cannot launch another native turn; owner continuation still needs retained custody, cleanup evidence and an explicit bounded extension.

The board shows frozen thresholds, actual usage, cached input, overshoot in tokens/seconds and whether the next turn is blocked. Accounting samples every 500 ms, includes waits while the supervised process is alive and excludes paused wall time. Native counters arrive at harness-defined boundaries: unreported in-flight generation can overshoot. Overshoot is retained, never clamped or estimated away. Reconciliation checks persisted usage before spawning another native process. Legacy installations without Day-1 tuning retain their approved bounds and calibration behavior.

`bun scripts/qualify-delivery.ts` retains real native command-denial evidence for the known live signing socket, a known credential path (open only, contents never printed), publisher writes, dependency/toolchain writes, external hosts and a dry-run QA push. It is a negative probe, not full provider renewal. Version-1 delivery evidence is invalid. Publishing stays blocked without version-2 isolation evidence, full native-tool qualification, and a launcher-published GitHub-verified signature on the tested tree. The old `qualify-delivery` command cannot promote partial evidence.

Trusted setup archives linked Git metadata, preserves edits and gives workers standalone unsigned Git metadata and copied dependencies. Dependencies and pinned executables are read-only under the native command policy. Scratch is `.factory-tmp`; commands have no internet or publisher socket. Native Codex tool calls keep the filesystem boundary on resume. Claude's policy has no allowed external domains and forbids arbitrary Unix sockets; renew its native qualification before claiming this changed policy proven.

PUBLISH is a launcher function called only after successful native completion and verified descendant cleanup. It rechecks the retained claim, assigned paths and original expected base. It snapshots the worker bundle into private storage, imports it into a fresh trusted checkout with hooks disabled, refuses merges, unexpected ancestry and out-of-scope intermediate edits, then re-tests the exact tree in the worker sandbox without credentials. A failed test, tree mismatch or dirty checkout refuses signing. The launcher alone signs a tree-only commit on the expected base, verifies it, rechecks custody and pushes only the fixed assigned `feat/factory-*` branch over HTTPS using the existing gh login, then opens its QA PR. There is no worker-facing signing or publishing server, separate App, merge or deploy operation. Original bundles/checkouts and private test receipts are retained. Undo through a signed revert; archive operational assets.

The per-run native permission settings explicitly allow `Bash` so supervised sessions can run approved local commands without an unavailable approval prompt. Shell sandboxing remains required with unsandboxed commands forbidden; this allow rule is never a substitute for actual outside/private read/write denial evidence. Without the explicit rule, compound commands can be refused despite sandbox auto-allow settings.

Termination records descendant process groups during execution, pins observed processes to their start identities, and sends TERM then KILL after three seconds even if the leader exits. This covers native tools that create separate groups and observed orphans. Processes that escape observation between samples still require execution-boundary containment proof. Missing process-table access fails cleanup rather than silently proving success. Failed or interrupted work keeps retained custody.

Supervisors start detached in their own process groups with ignored stdio. `unref` alone does not detach a process: launchd terminates remaining members of the tick's group when that short job exits, interrupting supervisors and their process-table probes. Keep launchd's default group cleanup enabled; do not use `AbandonProcessGroup` to mask a shared-group launch. Process-table probes use `/bin/ps` with the C locale; failures retain exit/signal diagnostics, and halt events record received signals independently of later tick stop requests.

Cleanup keeps collecting descendants while stopping, signals pinned owned processes individually as well as their groups, and verifies both observed processes and group membership disappear after KILL. Unreaped zombies are treated as exited. A native group `EPERM` is retained diagnostically and does not abort the other stop attempts; success still requires process-table proof of no live survivors. Survivors or process-table errors fail cleanup; they never produce a successful receipt. The private append-only `worker-cleanup` event retains group IDs, denied signals and verification status.

Each tick checks qualification expiry before GitHub reconciliation, including while paused or idle. Within two hours (or when already expired), each valid provider qualification queues one line through the existing Telegram bridge's `messages` outbox. Stable provider/expiry IDs prevent duplicate alerts on ticks, restart or a crash between stores. Renewal with a new expiry can alert again. The bridge defaults to `~/.alido-private/mail/mail.sqlite`; `FACTORY_MAIL_DB` selects an existing installation for rehearsals. Missing/failed bridge access records an append-only failure and retries on later ticks. No bot, credentials, model call or replacement mail database is created. Retain queue/delivery receipts; undo policy changes with a signed revert and retain prior alerts. Alerting neither renews qualifications nor admits workers.

## Owner actions and releases

Board writes require the private bearer token plus an exact loopback Origin. DNS-rebound Host values are refused; no CORS or schedule/funding operation exists. Reads are loopback-only. Text from GitHub is rendered as text, never HTML. English and French control labels are included.

`FACTORY_OWNER_TOKEN` authorizes `bun scripts/control.ts pause|resume`, `qa-accepted REV DAY RECEIPT`, `release qa|production REV RECEIPT`, or `clear-aws-stop OWNER-DECISION-RECEIPT`. Do not pass this environment to workers. Pause persists and blocks admissions/promotions; active supervisors stop and retain work. Resume does not replay claims or clear an overrun stop. `continue-session SESSION RECEIPT` is the separate owner-authorized bounded Codex continuation: stopped paused custody, exact retained native ID, verified cleanup and a larger calibrated token estimate are required. It spawns the normal supervisor transactionally, resumes the native conversation in the preserved workspace, retains original brief/start/claims/debits and monotonic accounting, and records the explicit extension and prior stop. Paused wall time does not become active usage. The original time bound is unchanged. New attempts retain distinct logs and events; no automatic retry is added. The board can answer questions and request a ticket stop. After reconciling native custody and preserving work, use `bun scripts/control.ts archive SESSION CUSTODY-RECEIPT` with the owner token, or the board's archive form. Only unknown, paused or finished sessions can be archived, and a still-live supervisor refuses archive. Custody records bind PID to boot identity and process start (plus UID on macOS), so a reused PID cannot block archive; ESRCH and EPERM are treated as no owned supervisor. Legacy rows without identity retain the live-PID refusal until custody is reconciled. A stopped supervisor clears its PID only after its child exits. Archive releases slot/heavy-slot/path occupancy, retains session/native IDs, workspace, original claims and irreversible debits, and appends the prior status, receipt and undo guidance. Archive alone never enables replay; a separately approved new digest can qualify for the numbered retry path above. Unknown/paused sessions deliberately keep occupancy until this explicit reconciliation. A crash with starting/running custody still requires native-session investigation; no automatic retry or reset is supplied without the new-digest approval and archived-custody checks above. The source token, not a caller-supplied role name, authorizes these operations.

Release authorization refuses any other minute, duplicate daily batch, absent QA acceptance, mismatched revision or paused state. Production requires the same day's independently accepted QA revision. This is a local execution guard and evidence record, **not a deployment receipt**. Integrate it with the private project's protected executor before its effects; separate workflow-side time enforcement and AWS OIDC/brakes belong to the infrastructure setup. No product deployment is performed by this repository. Receipts displayed here are not claimed as independently deployed truth without project readback evidence.

## Restart and undo

A stable claim is committed before the spawned supervisor can acquire database custody. An atomic supervisor claim prevents two supervisors from executing it. A crash between commit and spawn can strand a claim; it cannot cause a duplicate start. Reboot preserves pause, native IDs, original estimates, paths, debits and unknown custody. Reconcile the real native session and preserved worktree before any continuation; do not clear claims or refund a wallet to retry.

`prepare` writes absolute-path plists under the private installation; existing files are preserved. It does not bootstrap jobs. After review, install uses `launchctl bootstrap gui/UID PATH`. Undo loaded jobs with `launchctl bootout gui/UID/com.agent-factory.tick` and the corresponding `.board` label. Archive plists and private state rather than deleting them. To undo source changes, make signed revert commits; retain public history. Stop the manually started board with SIGTERM to its process. Archive worktrees only after custody acceptance. Caps and the schedule are never changed by installation or rollback.

Qualification still needs actual live-meter, stop/descendant, isolated-policy and phone steering rehearsals. Tailscale, phone access, Telegram, production workflow enforcement, AWS billing ingestion and external brakes are not installed or represented as passed.

Primary interface references: [Bun SQLite](https://bun.sh/docs/api/sqlite), [Codex non-interactive execution](https://developers.openai.com/codex/noninteractive/), [Claude CLI](https://code.claude.com/docs/en/cli-reference). Installed local help is checked for supported flags; runtime qualification, not vendor documentation, decides admission.


## Project enrollment

`factory add-project <owner/repo> [--dry-run]` (or `bun run factory -- add-project <owner/repo>`) uses the signed-in `gh` account for read-only issue backfill. It preserves comments and unrelated policy bytes, requires a block-style `projects:` mapping, and validates the proposed config before writing. A source error or the 1,000-issue cap refuses enrollment. Existing enabled projects are refused; existing read-only entries refresh without duplication. Empty owners prevent admission on future ticks; this command never runs a tick or worker.

Run setup with one policy writer at a time. Before replacing config it checks for intervening changes, archives the original under private `archive/add-project-UUID/config.yaml`, then records snapshots and an append-only undo event. Config and SQLite are separate files: interruption between writes can leave an enrolled entry without snapshots; repeat the command to recover. Undo by restoring the archived config after checking for later policy edits; retain the archive, snapshots and events. Dry run uses only an in-memory database and writes nothing, including no receipt; save its output privately when evidence is needed. To rehearse actual writes without live enrollment, copy config into a private staging directory and set `FACTORY_PRIVATE_DIR` to that directory.

CI runs on GitHub-hosted Linux for pull requests and main/QA pushes: Bun 1.3.14, frozen install, strict typecheck and tests. Actions are pinned to commit SHAs; permissions are read-only and no secrets or AWS runners are used. `Verify` is the branch-protection check.

## Local usage and forecasts

Both providers are read without model calls. Each production tick also queries the installed Codex app-server with `initialize` and `account/rateLimits/read` (`excludeResetCreditDetails: true`), without creating a thread or turn. The query has an eight-second deadline and a 256 KiB response bound; unavailable, malformed or unsupported status falls back to native receipts without changing their observation time. Only the `codex` bucket and its actual primary/secondary windows are retained, never account identifiers or credits. A successful query is observed at response time. Claude CLI currently has no non-model subscription-status command; its authentication status is not quota evidence. Codex reads primary/secondary rate-limit events from bounded 256 KiB tails of the 20 newest rollouts across session date directories, including active sessions started before today. Claude reads bounded tails of the 20 newest top-level project session JSONL files, accepting structured top-level `rate_limits.five_hour` / `seven_day` metadata with `used_percentage` and `resets_at`, or timestamped `rate_limit_event` records with `rate_limit_info.unifiedWindows` utilization and reset fields. Both formats require the original event `timestamp`; file modification time never supplies quota freshness. Reset values may be epoch seconds or ISO dates. A session containing prose about quotas or only token counts supplies no subscription reading. Native versions that do not persist this metadata remain unknown; this implementation does not claim a successful live Claude reading from those versions. Existing validated private `readings.json` remains an input. Each tick rereads local evidence before GitHub reconciliation. Newer local evidence wins, even when partial; observation age is never refreshed by polling. A missing window is never copied from another observation or invented from an allowed status. Unreadable receipts do not hide other receipts. Ordinary admission refuses missing readings (or fewer than two windows under the legacy policy), expired resets, future timestamps and readings older than 15 minutes.

To prevent an idle installation locking itself out, the launcher may atomically admit exactly one approved, qualified, unpaid, non-heavy ticket with effective bounds at most 30 minutes and 8M tokens when usage is missing or stale and there is no active worker custody. All other admission gates still apply. Known 70/90% thresholds, future timestamps, wrong-provider evidence and invalid native evidence are never bypassed. The private `usage-bootstrap-admission` event and durable global allowance bind the exact session and approved bounds. Its initial supervisor may pass the same missing/stale check for at most two minutes after admission; continuations cannot use it. Concurrent ticks, restarts, worker failure, completion and archive do not grant another allowance. A genuinely newer fresh native reading for that provider, observed after admission, rearms recovery and records `usage-bootstrap-refreshed`; polling a receipt never makes it fresh. If the bounded run fails to produce native quota evidence, further recovery stays visibly refused pending real evidence. Undo via signed revert after reconciling custody; retain the allowance/events and all operational assets. The board shows observation age, resets and the 70/90% gate.

Run `bun estimator/refresh.ts` explicitly to refresh closed issue and PR timings for the factory and configured trial product. This is read-only GitHub access, no model calls and no launch. Each source is bounded to 10,000 rows; errors or truncation retain the previous snapshot. Snapshots and source receipts stay in private SQLite with append-only undo evidence. Refresh after new completed work, rather than querying GitHub per prediction. Imported/migrated labels and Linear/import provenance in the body exclude a row from training. GitHub creation-to-close time is elapsed time only: it never supplies helper-hours, tokens, provider identity or percentage usage. Historical migrations without such labels must be excluded in the private evidence before using their elapsed timing for scheduling.

Successful native worker completion retains an actual receipt from monotonic process accounting. Helper-hours conservatively include waits while that process is alive; they are not claimed as measured active-turn time. Missing/zero native token evidence remains unknown. Provider token counts cannot be converted to subscription percentages. Historical helper-hours/usage remain unknown until native actuals exist. Intake may include `area` and `kind` to identify comparable work (otherwise `unknown`).

The deterministic `recent-five-v1` estimator predicts helper-hours, native tokens and elapsed hours. It compares the last five earlier comparable tickets with the mean of all earlier comparable tickets; fewer than three comparable records falls back to the provider pool. Chronological held-out evaluation trains only on records completed before each target's start. Promotion requires at least 20 held-out measurements of each dimension, at least 10% lower absolute error on helper time and tokens, and no worse elapsed error. Otherwise it is visibly `not-better` and forecasts use the mean. No history means null/unknown, never zero. The board shows the evaluation and each open ticket's preview; a successful reservation freezes its version, prediction and score privately before launch. Forecasts are advisory: they do not replace approved intake bounds or reset overrun baselines. Freeze receipts can be reconciled with the issue by the owner; this controller does not silently edit approved issue intake.

See [repository enrollment and worker qualification](enrollment.md) for the setup sequence. Every CLI tick writes exactly one timestamped JSON summary to stdout (the installed job’s `tick.log`): `status: "ok"` with ready/claimed counts, persistent `paused` state and per-ticket `refusals` (ticket ID and reason), or `status: "error"` with the failure. The board shows pause state and the last tick's refusals together in its heartbeat card. Errors also go to stderr and exit nonzero.


## Owner event wake and recovery

The launcher queues stable events for ready tickets, returned reviews, completed CI checks, exact release windows and qualification renewal two hours before expiry. A first PR reconciliation records a historical baseline without waking everyone for old reviews/checks. The native GitHub IDs and head bind subsequent events; repeats and process restarts cannot dispatch a claimed event twice. Truncated or failed source reads retain the prior successful reconciliation timestamp. The board shows that timestamp separately from tick heartbeat.

Register an owner with the owner-token control: `register-owner ROLE WORKSPACE NATIVE-ID|new PID|0 RECEIPT`. Registration verifies the exact existing native transcript, workspace and optional live process identity. It records the prior registration and undo. Register active external owner sessions with their actual PID so the launcher waits for them instead of duplicating a running owner. Missing registration leaves events queued. New owners start once; later events run `codex exec resume NATIVE-ID` (Claude uses its native `--resume`). The original native ID is retained. No GUI foreground open is counted as a resumed turn.

Owner wakes are bounded read-only reconciliation turns: read-only source/toolchain/dependencies plus per-event scratch, without a signing agent or GitHub/AWS/controller credentials. Launcher-supplied event evidence and the owner record provide context; ticket implementation, publishing and release remain separate admitted effects. Each wake retains native model/counter/cleanup evidence, checks its input+output delta from the pre-resume native baseline and stops at the Day-1 bounds. Older transcript usage is never charged again as this event's work. Model and effort are checked on the new turn after a complete historical baseline read; historical model changes do not masquerade as a current-turn conflict. A conflicting/missing new-turn native receipt blocks completion. Exact retained historical native receipts can be found across their original date, rather than selecting the newest session.

A dispatch claim is committed before spawning. An uncertain start is retained, never automatically retried; an owner with unresolved cleanup prevents later dispatches. A stopped failed worker with a retained native ID and independently verified descendant cleanup can be archived automatically and queues one recovery event for its owner. Archive releases its worker slot/path occupancy, retaining workspace, native ID, ticket claim, debit and all logs. Duplicate recovery events resume the owner once; they never re-run the failed worker or reopen its ticket claim. A live/unknown supervisor, missing native ID or missing cleanup proof keeps custody blocked. Original budget pauses remain owner-reconciled, not auto-archived. Undo source with signed revert; preserve operational evidence and registrations.

## Executable delivery checks

The approved intake `test` must be an executable local command. Put human acceptance instructions in `outcome`. Delivery rejects prose before native work and runs checks under Bash with `errexit` and `pipefail`, so a later successful whitespace check cannot conceal an earlier failed command. Failed publisher events include the session ID and the private tested-tree receipt path. A publisher refusal remains a failure even after native completion; cleanup-based archive preserves evidence and permits only a separately approved numbered retry.

On macOS, Bun 1.3.14 `bun run` may attempt to list home ancestors outside the restricted command policy and fail with `CouldntReadCurrentDirectory`. Do not grant home access. For a repository whose test script is Vitest, approve the equivalent explicit command `HOME="$PWD/.factory-tmp/home" node node_modules/vitest/vitest.mjs run --configLoader runner --no-cache PATH`. This keeps the test token in scratch, avoids config bundling into read-only dependencies and uses the repository configuration. Validate it against the actual repository before approval; never substitute it silently for a frozen command. Documentation tickets need concrete source assertions plus `git diff --check`, with manual/hosted acceptance reported separately.

New product workers resolve QA through authenticated GitHub readback and fetch that immutable revision before creating their workspace; the existing source checkout is never reset. Continuations preserve their original base. Missing prerequisite files are blockers; an unchanged bundle cannot publish and must not be treated as successful delivery.

Owner wake, qualification-renewal alerts and release-window events originate in the scheduled launcher without a Coordinator turn. Owner wakes are read-only. This repository does not yet execute full qualification renewal or protected project releases from those events. A queued/completed owner wake is not renewal or deployment evidence. Exact-window events cannot provide a catch-up release, and owner execution latency cannot extend the authorized minute.

## Work supply and bounded recovery (A4)

The optional `autonomy` policy opts into launcher-owned intake and rule approvals. Below **current worker slots + 3 unclaimed ready tickets**, the launcher queues a fresh Product intake turn. Intake and failure diagnosis have priority over routine owner notifications and start fresh native sessions. Owner tools retain read-only source and their per-event writable scratch. They write data to `intake.json` or `retry.json`; only the trusted launcher makes GitHub changes. Only native-verified completed wakes with verified cleanup can supply effects. JSON is size bounded, schema validated and opened without following symlinks. Missing evidence never becomes qualification or delivery success.

`autonomy.intake_mode` is `drain` (the default) or `build`. Drain clears existing work before reprioritization: no new Alido product scope, even when the buffer is empty. Intake may create repairs (`kind: fix`) only with `brief.intakeEvidence` referencing an existing open issue/PR in the same repo (`{"kind":"issue","number":123}` or `{"kind":"pr","number":123}`), or a recorded failed session in that repo (`{"kind":"session","session":"ID"}`). A factory self-ticket must target `fulmar-hq/agent-factory` and cite an exact excerpt of an A1–A9 step in the private installation's `autonomy-correction-plan.md` (`{"kind":"factory-plan","step":"A4","quote":"exact source excerpt of at least 20 characters"}`). The private plan is read as bounded data and stays outside Git. Missing, closed, unavailable or mismatched evidence refuses effects. References establish provenance; the owner must still keep the repair within the cited scope. Mode is checked at owner dispatch, draft creation and automatic approval, so a queued build wake cannot bypass a later drain setting. Empty drain intake is valid.
