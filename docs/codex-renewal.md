# Automatic Codex qualification

The existing scheduled tick records the earliest real Codex expiry and schedules a detached executor six hours before it. A changed worker/native/stop/publisher implementation, verifier or installed CLI makes it due immediately. The schedule is evidence of a future attempt, never qualification. Private `codex-renewal-schedule` retains `dueAt`, actual expiry, boundary hashes and claim identity.

The same immediate transaction as a normal capacity observation reserves one builder slot and the durable launcher-maintenance lease before spawning. Reviewed source integration and renewal cannot overlap. Missing usage, 90% usage, pause, full capacity or unknown maintenance custody refuses a start; no literal or allowance changes. A single claim binds original qualification bytes and material fingerprint. Interrupted or failed attempts never replay automatically. Known cleanup releases the slot; unknown cleanup retains custody.

The trusted executor uses the existing subscription CLI, with API/provider/credential environment removed from native tools. Isolated rehearsal custody is not production ticket admission and contains no synthetic passing qualification. Both medium and high run a new command and native-tool 12-check security probe, the original 25-second/50-second time guard with a TERM-ignoring descendant, and an independent 100-token/200-token stop. Known protected targets must exist. A denied credential open never reads its contents. The probe is hashed before and after, native tool invocations must run that exact generated probe once, and raw process snapshots, actual successful signal sends, positive live accounting and native identity/model/effort/termination are retained.

The source verifier rereads all six raw native/capture receipts and hashes. Any failed, unsupported, contradictory, late or missing proof refuses replacement. Reports distinguish proposed proof from adoption. Original qualifications and publisher authority, prepared replacement, native IDs, old restart evidence and small receipts remain private. Before atomic replacement the executor rechecks qualification bytes, source/CLI, policy, monotonic clock, actual tested-tree publisher receipt and fresh GitHub verified signature. Claude and the explicit phone-deferred waiver remain unchanged. Publisher authority is separately verified, never inferred solely from worker probes.

A persistent uncertain-adoption flag blocks new Codex admission before replacement. It clears only after rename, directory fsync, byte readback and the recorded adoption transition. Partial failures do not roll back over newer evidence or manufacture success. Failure-only Alido Mail alerts use one durable attempt ID; missing bridge access retries the notification on later ticks without repeating any native probe. Success and due scheduling send no Vincent message.

The tick's installed launchd cadence supplies scheduling; no separate renewal timer or polling model exists. After reviewed source installation, read the live schedule and its next Toronto time, retained global lease, six-run manifest/adoption receipt and subsequent real claims. A live six-run rehearsal and multi-day endurance are distinct observations; fixture passes cannot supply them. Undo via signed source revert after custody reconciliation, retaining every run, claim, report and debit. Restoring an old qualification never extends its expiry.

Publisher authority requires a real execution under the matching loaded source, Git/Bun toolchain and private-policy hashes. The supervisor entry captures source before dynamic import, rejects changes during import/work, and retains the exact implementation and tested-tree receipt after protected publication. An old receipt from another implementation never extends authority. Renewal waits for this proof before claiming any native probe, then rereads the same proof and remote signature/tree before adoption. Publisher expiry is capped at24hours from that actual execution; its earlier expiry also advances the renewal schedule. Missing proof leaves a scheduled next60second check, never qualification.

The installed CLI uses code-mode command receipts. Security permits only the canonical literal `text(await tools.exec_command({"cmd":"EXACT_BOUND_COMMAND"}));` wrapper, no extra code, keys or tool retries. Its correlated raw command response must exit0 and agree with the CLI command-execution item and native twelve-check output. Lifecycle wrappers permit only the known probe command and empty stdin waits on returned session IDs; actual native identity/accounting, successful controller signals and bounded complete cleanup remain independently required. The code-mode host stays enabled; disabling it was a retained failed protocol smoke, never qualification. Qualification tickets keep the standalone Git permission profile but omit the ordinary delivery prompt, since the probe creates its own unsigned bundle once.

Successful adoption retains the exact qualification bytes, material fingerprint and publisher receipt/expiry already covered. If only an aged unchanged publisher proof makes the schedule due while worker coverage remains fresh, later ticks wait for genuinely new publisher evidence rather than repeat six native runs that cannot extend authority. Expiry is never advanced from a retained schedule or repeated old proof.

The alarm includes publisher v2 among required qualifications, so waiting for a new delivery cannot silently conceal approaching publisher expiry. Its verified observation requires current implementation/policy, the retained tested/signature readback and the same adopted Codex bindings. Automatic adoption records per-key Codex hashes; an unrelated later Claude qualification update cannot invalidate otherwise unchanged Codex or publisher evidence.

macOS can report a generic resolver error8 for a blocked lookup; this is never relabeled EPERM. The trusted parent resolves known GitHub/example IPv4 targets before probes and verifies them again before adoption. The canonical native probe sends an actual benign DNS query to1.1.1.1:53, requires its real EPERM/EACCES plus denial of the preflight-known example transport and failure of the sandboxed resolver, and tests the preflight-known GitHub transport and Git dry-run with a pinned resolver. The retained network targets/time bind the generated bytes. Permission-denial fields still accept only1 or13; generic DNS/auth/local Git failures cannot supply them.

The tick evaluates renewal both after fresh usage ingestion and again immediately before ordinary work admission. Slow GitHub reconciliation can outlive a builder cohort; the second atomic check lets due renewal reserve one existing free slot before replacements fill the cohort. Neither check skips usage, pause, disk, current publisher proof or shared-lease custody, and retained attempt IDs prevent duplicate native starts.

The installed CLI writes literal JavaScript data keys in code-mode stdin waits and exits0 after a handled SIGTERM without a turn-aborted record. The reader permits only the same whitelisted literal data keys, never arbitrary JavaScript. A graceful0 stop requires a live bound root before the threshold, actual successful owner TERM, root exit within1.5seconds, no native completion/error, bounded child cleanup and final absence. A zero status alone supplies no stop evidence; nonzero un-signaled exits still require the correlated abort record. The first live attempt and its refusal remain retained; no expiry was advanced from its parser failure.
