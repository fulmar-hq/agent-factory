# Enroll a repository and qualify a worker

1. Review the repository’s AGENTS.md, governing contracts and test commands. Use `factory add-project owner/repo --dry-run`, then `factory add-project owner/repo` for a new read-only project. Existing enabled projects need no repeat enrollment. Review the private config owner assignments before enabling work.
2. In private `repositories.json`, map `owner/repo` to an absolute path of an existing Git checkout, for example `{"example/site":"/absolute/path/to/site"}`. The value is the **source checkout**, not a folder containing worktrees; workers branch from that checkout’s HEAD. Verify its remote and intended base first. Worktrees are created at `FACTORY_PRIVATE_DIR/workspaces/<session-id>`. To use a different worktree root, the Coordinator can create that private `workspaces` path as a symlink to the desired root before enabling workers; preserve/archive any existing directory first. Do not reset existing checkouts or worktrees.
3. Qualify each provider’s supervised **print** adapter independently. Collect the CLI version and exact configured model/effort, actual subscription login, restricted execution boundary (controller policy/state/credentials excluded), continuous token accounting and token/time stop rehearsals including descendants, native session custody, and actual phone steering/stop (or the explicit Coordinator phone deferral in step 4). Final token totals, a desktop deep link, filesystem modes and prompts are insufficient evidence. Keep receipts private.
4. Only after every non-waived rehearsal passes, write that provider’s private `qualifications.json` entry with `qualified`, `subscription`, `policyIsolation`, `liveAccounting`, `stopVerified` all `true`; `phoneVerified: true` or, only when the Coordinator deliberately defers remote access, `phoneVerified: false` with `"waiver": {"phone": "deferred"}`; `version`, `model`, `effort`, future epoch-millisecond `expiresAt`, and `evidence` pointing to the actual receipts. Until then omit the provider or use an explicitly unqualified entry. Never manufacture success to satisfy the schema. Model/effort must match the owner or ticket override; requalify after material adapter or boundary changes. The stored version is a receipt, not an enforced version equality check.
5. Confirm fresh two-window subscription readings and billing where needed, available capacity/wallet, bounded disjoint ASCII paths, and the reviewed content-bound approval label (`approve-intake`). Watch the next tick and board. Missing/expired qualifications or stale/unknown readings refuse starts. No model runs just to poll. Preserve all native logs, worktrees and claims; archive only with a custody receipt. Undo enrollment by restoring the archived config after reconciling later changes; undo qualification by archiving/replacing its entry with an unqualified record. Never refund debits or reset launched ticket claims.

Codex polls its exact native rollout for live cumulative usage; Claude reconciles streamed usage and its exact transcript. Both stop at the original observed token budget. Neither adapter establishes an independent same-user execution boundary merely by setting flags. Missing native stop receipts or boundary proof are qualification blockers, not setup checkboxes. This guide does not authorize putting `true` in those fields without new evidence. Native refusals must be retained and never replaced with a successful qualification.


Owner-run disposable rehearsals may call `claimSupervisor` and `superviseSession` with an explicitly seeded private **rehearsal** store and throwaway Git worktree. This uses the same custody, adapter, accounting and stop code as production without manufacturing a passing qualification or admitting a real ticket. It does not test production intake/admission; that path continues to require all qualifications. Record this distinction with the receipts. Never use this route against an operational store or product repository. Kill/restart only the disposable launcher, preserve its stable claim, observe native-session counts, stop through its private store, then archive with `Engine.archive`. Record any rehearsal that finishes before its stop or crash as unproven for that case; do not infer a pass from fixture tests.
